# A registry of operations that preserve the runtime invariant

Each public operation family contributes one local proof that it preserves the global runtime invariant from any valid starting state. These theorems register the return-selection, restart, revocation, system-call, mapping, message, and transfer families, so that the per-family proofs can later be combined over arbitrary mixed sequences of operations.

- `runOperations_preserves_runtimeWellFormed` — If every individual operation in a list preserves the kernel-wide consistency guarantee, then running the whole list back-to-back preserves it too; this is the reusable stepping stone for the universal theorem.
- `selectUserReturn_operationPreservesRuntimeWellFormed` — Arming return-to-user authority is registered as an operation that always preserves the kernel-wide guarantee.
- `userReturn_operationPreservesRuntimeWellFormed` — The outgoing return-to-user operation always preserves the kernel-wide guarantee: a valid return changes nothing else, and every refused return sets both halt records consistently before anything continues.
- `restart_operationPreservesRuntimeWellFormed` — Bookkeeping: the restart operation is registered as always preserving the kernel-wide consistency guarantee.
- `capabilityCopy_operationPreservesRuntimeWellFormed` — Permission copying preserves the kernel-wide guarantee for both outcomes: acceptance publishes the exact fresh permission store, and every denial leaves the state untouched.
- `capabilityRevoke_operationPreservesRuntimeWellFormed` — Direct revocation is fail-closed: any attempt to remove authority that live resources still need becomes a refusal that changes nothing, and every accepted removal supplies exactly what the kernel-wide guarantee requires.
- `capabilityRevokeSubtree_operationPreservesRuntimeWellFormed` — Lineage-wide revocation follows the same fail-closed rule while also clearing every permission derived from the revoked one.
- `syscallAccess_operationPreservesRuntimeWellFormed` — A system call that decodes to a memory access check preserves the guarantee: a successful check changes nothing but the reply, and every failed translation is an ordinary refusal that leaves the state as it was.
- `syscallDecodeRejected_operationPreservesRuntimeWellFormed` — Any system call the decoder cannot parse, no matter what attacker-controlled words it carries, is refused with the exact error surfaced and the kernel state left literally untouched.
- `map_operationPreservesRuntimeWellFormed` — Bookkeeping: the raw mapping operation is registered as preserving the kernel-wide guarantee for accepted and refused outcomes alike.
- `unmap_operationPreservesRuntimeWellFormed` — Bookkeeping: raw unmapping is registered likewise, with acceptance also evicting the cached translation.
- `protect_operationPreservesRuntimeWellFormed` — Bookkeeping: raw page-permission tightening is registered likewise for both outcomes.
- `syscallMap_operationPreservesRuntimeWellFormed` — A system call that decodes to a mapping request preserves the guarantee: once the generation-checked handle resolves, the only effect beyond the raw mapping is re-arming the caller's return authority on an already consistent state.
- `syscallUnmap_operationPreservesRuntimeWellFormed` — A system call that decodes to an unmap request preserves the guarantee: acceptance publishes the unmapping, evicts the cached translation, and re-arms the caller's return authority, while every refusal changes nothing.
- `syscall_operationPreservesRuntimeWellFormed` — Every possible system call word tuple preserves the kernel-wide guarantee, because decode failure, mapping, unmapping, and access checks are the entire vocabulary a call can decode to.
- `runSyscalls_preserves_runtimeWellFormed` — Any finite mixture of accepted and refused raw system calls, run in sequence through the real gate, preserves the kernel-wide guarantee.
- `dispatchIPC_send_classifies` — A stepping-stone fact used by later theorems: a message send has exactly three possible replies, namely sent, refused at the handle check, or refused by the endpoint.
- `ipcSend_operationPreservesRuntimeWellFormed` — Sending a message preserves the kernel-wide guarantee in every case: the single success path is covered by the accepted-send theorem, and each refusal leaves the state unchanged.
- `dispatchIPC_receive_classifies` — A stepping-stone fact used by later theorems: a message receive has exactly four possible replies, namely a pending sealed transfer, a delivered message, a refused handle, or an endpoint refusal.
- `ipcReceive_operationPreservesRuntimeWellFormed` — Receiving a message preserves the kernel-wide guarantee in every case: delivery, sealed-mailbox protection, ordinary refusal, and busy-or-halted absorption are all covered by one theorem.
- `ipc_operationPreservesRuntimeWellFormed` — The whole public messaging interface is one preservation family, so trace-level proofs can quantify over an arbitrary untrusted messaging call without examining its shape.
- `transferOffer_operationPreservesRuntimeWellFormed` — Every public sealed hand-off offer preserves the guarantee: authority or handle failures change nothing, and success records exactly the pending gift and its notification message without weakening anything else.
- `transferAccept_operationPreservesRuntimeWellFormed` — Every public sealed hand-off collection preserves the guarantee: malformed, stale, or unavailable receipts change nothing, while a delivery consumes the message and installs the authority in one consistent step.
