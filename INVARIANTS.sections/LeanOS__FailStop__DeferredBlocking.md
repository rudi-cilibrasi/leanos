# Every operation keeps sleeping programs consistent

The kernel keeps a stronger invariant for programs asleep in message waits and for cancellations deferred after a contained fault. These theorems inventory every operation family and prove that each one preserves that blocking invariant, including program termination and contained faults that must detach sleeping peers.

- `runtimeTraceOperation_preserves_runtimeWellFormed` — Every operation admitted to the registered trace surface has a complete one-step preservation proof covering all of its possible results.
- `runtimeTraceOperation_complete` — The registration inventory is exhaustive: every public operation is represented, so a newly added operation cannot silently escape the universal theorem below.
- `operation_preserves_runtimeWellFormed` — Every public operation preserves the kernel-wide consistency guarantee for every possible result, with no registration premise and no excluded case.
- `gate_preserves_runtimeWellFormed` — The gate itself preserves the kernel-wide guarantee for an arbitrary operation, including attacker-controlled argument words and terminal modes.
- `runRuntimeTrace_preserves_runtimeWellFormed` — Any finite interleaving of all registered operation families, with arbitrary calls and handles, preserves the guarantee; sequences continuing past a halt are covered too, because the gate absorbs them.
- `runOperations_preserves_runtimeWellFormed_universally` — Any finite sequence of operations whatsoever preserves the kernel-wide guarantee, with no side condition on any member; this is the universal preservation result for the gate.
- `blockingIPCContext_terminate_preserves_contextAgreement` — Removing a program from the blocking store keeps the waiter index and the saved-context bank in exact agreement, deliberately without assuming anything about the scheduler side.
- `publishInterruptCleanup_preserves_contextAgreement` — A stepping-stone fact used by later theorems: the interrupt cleanup publisher keeps the waiter index and saved-context bank in exact agreement.
- `interrupt_contained_preserves_contextAgreement` — Contained-fault cleanup preserves exact waiter and saved-context agreement while the invalidated peers move into the separate deferred-cancellation bank.
- `interrupt_contained_faulting_identity` — A contained fault always blames the program the kernel's own execution record named; combined with the entry-time binding it therefore blames the officially current program.
- `contained_faulting_identity_is_current` — Given the entry-time binding between the executing program and the kernel's roster, the program blamed by a contained fault is exactly the roster's current program.
- `detachTerminationSource_preserves_deferredBlockingRuntimeWellFormed` — Normalizing a victim's blocking state before cleanup preserves the full deferred-cancellation classification: at most one exact waiter, index, and context triple is removed, and every peer waiter, retained cancellation, and disjointness fact is inherited unchanged.
- `publishTerminationDetachment_preserves_deferredBlockingRuntimeWellFormed` — The shared current-program cleanup publisher establishes the complete deferred-cancellation state afterwards; being the current program rules out the only possible collision, an idle retained identity that is also the program being retired.
- `detachedAcceptedTermination_preserves_deferredBlockingRuntimeWellFormed` — Accepted termination may target a blocked, deferred, or otherwise non-current program; detaching that identity first puts things in the form the shared publisher needs while preserving the complete deferred classification.
- `installTerminatedSubject_accepted_preserves_deferredBlockingRuntimeWellFormed` — Explicit accepted termination lands on exactly the same blocking, retained, and saved-context records as detach-then-shared-cleanup, so the stronger deferred classification carries over without being rebuilt.
- `gate_terminateSubject_preserves_deferredBlockingRuntimeWellFormed` — Explicit termination preserves the complete retained-context classification for every gate outcome: refusals and busy-or-halted results change nothing, and acceptance first detaches any blocked or already-deferred target and then publishes the authoritative cleanup.
- `publishInterruptCleanup_preserves_deferredBlockingRuntimeWellFormed` — Current-program cleanup is the first consumer of the reusable detachment fact: a current program is never an indexed waiter and never an idle retained cancellation, which is exactly what that fact requires.
- `installTerminatedSubject_current_preserves_deferredBlockingRuntimeWellFormed` — Explicitly cleaning up the current program preserves the complete deferred classification; the extra clearing of its retained slot equals the already-empty slot the shared proof establishes.
- `interrupt_contained_preserves_deferredBlockingRuntimeWellFormed` — Contained-fault cleanup establishes the complete deferred-cancellation state whenever the faulting program is the current one; that binding rules out the only otherwise possible collision with a retained identity.
- `gate_terminateCurrent_preserves_deferredBlockingRuntimeWellFormed` — Scheduler-selected termination preserves the complete retained-context classification for every result: a missing current program and every busy-or-halted outcome change nothing, and acceptance retires the current program through the shared cleanup publisher.
- `interrupt_contained_clears_faulting_deferred` — After contained cleanup the faulting program's retained slot is empty; without the identity binding, exactly the stale idle identity this premise exists to exclude could have survived.
- `interrupt_contained_defers_invalidated_waiter` — The precise point-by-point cleanup law for a contained fault: the invalidated peer's saved context is parked in the deferred bank with its validity, its idleness, and its remaining address-space authority all spelled out.
- `blockingContextAgreement_of_projections` — Bookkeeping: if a step leaves the waiter index and the saved-context store untouched, waiter and context agreement carries over unchanged.
- `publishTerminatedBlockingSubject_preserves_contextAgreement` — Bookkeeping: publishing a terminated program to the blocking view keeps waiter and context agreement whether the termination was accepted or refused.
- `dispatchIPC_preserves_contextAgreement` — Bookkeeping: a messaging call never touches the waiter index or the saved-context store, so their agreement is preserved.
- `installTerminatedSubject_preserves_contextAgreement` — Bookkeeping: the explicit termination installer preserves waiter and saved-context agreement.
- `gate_preserves_blockingContextAgreement` — Every operation through the gate preserves exact waiter and saved-context agreement: operations unrelated to blocking keep both stores literally, and termination removes the indexed waiter and its saved context together.
- `gate_blockingStateNeutral_preserves_blockingIPCContext` — An operation in the blocking-neutral family leaves the entire typed blocking state literally unchanged, not merely the agreement between its parts.
- `gate_blockingStateNeutral_preserves_blockingRuntimeWellFormed` — The blocking-neutral family preserves the full blocking runtime guarantee for every result and every execution-latch mode.
- `gate_syscall_preserves_blockingRuntimeWellFormed` — Every raw system call keeps the full blocking guarantee: denials change nothing, access checks touch only return-control state, and accepted map or unmap requests reuse the scheduler-preserving memory path before re-arming the caller's return authority.
- `gate_transferOffer_preserves_blockingRuntimeWellFormed` — A sealed hand-off offer preserves everything waiters were validated against: acceptance records a pending gift and its sealed message but keeps the program, object, kind, and live-slot registers exact, while refusals change nothing at all.
- `gate_transferAccept_preserves_blockingRuntimeWellFormed` — Collecting a sealed hand-off preserves the blocking guarantee: delivery may fill one verified-empty permission slot and consume one message, but every waiter's existing authority and every other message survives; refusals change nothing.
- `gate_capabilityCopy_preserves_blockingRuntimeWellFormed` — Permission copying preserves the blocking guarantee: acceptance fills one verified-empty slot and keeps every authority an indexed waiter already holds, while denials and busy-or-halted outcomes change nothing.
- `installReceiveAuthorityPreservingCapabilities_preserves_blockingRuntimeWellFormed` — Publishing any permission state that keeps all receive authority carries the full blocking guarantee: a waiter's authority may live in a different surviving slot afterwards, but the waiter can never lose its right to the endpoint it is waiting on.
- `installRevokedSubtree_preserves_blockingRuntimeWellFormed` — Publishing an accepted whole-family take-back together with its in-flight cancellations keeps every sleeping program's receive authority and the blocking invariant intact.
- `gate_capabilityRevoke_preserves_blockingRuntimeWellFormed` — Direct revocation preserves the blocking guarantee: the guard refuses to remove receive authority, so every accepted removal leaves each indexed waiter with a witness of its endpoint right, and refusals change nothing.
- `gate_capabilityRevokeSubtree_preserves_blockingRuntimeWellFormed` — Lineage revocation obeys the same boundary: any permission subtree containing receive authority is refused outright, and accepted removals keep every indexed waiter authorized for its endpoint.
- `gate_createSubject_preserves_blockingRuntimeWellFormed` — Creating a program preserves the blocking guarantee: only one fresh identity is promoted, so every existing waiter, mailbox, scheduler member, and saved context keeps the same authority and position; refusals change nothing.
- `gate_scheduleAdd_preserves_blockingRuntimeWellFormed` — Queue admission never wakes a waiter: a successful admission appends only a runnable program with an already-staged context, and no waiter is ever runnable, so none can become the new ready member; refusals change nothing.
- `schedulerTick_preserves_blockedView` — A scheduler tick preserves every roster fact a blocked waiter observes and cannot rotate a program that was neither current nor ready into either selected position.
- `resumeSwitch_preserves_quiescent_context_absence` — A switch can only save or select programs that were current or in the ready queue, so a program absent from the kernel-owned context bank stays absent through every accepted switch, refusal, and fatal entry.
- `resumeSwitch_preserves_quiescent_scheduler_view` — An idle program stays idle through a switch: refusals and fatal entry keep the scheduler literally, and an accepted switch publishes exactly the tick rotation covered above.
- `blockingIPC_wellFormed_tick` — A scheduler tick cannot make an existing endpoint waiter runnable, current, or ready, because the rotation touches only the old current program and the existing ready queue, both of which exclude every waiter.
- `resumeSwitch_noError_preserves_blockingIPCWellFormed` — A successful save-and-restore switch publishes exactly the scheduler tick, so the waiter-excluding rotation fact carries over to its blocking view.
- `gate_resumePreempt_preserves_blockingRuntimeWellFormed` — Every preemption outcome retains the stronger blocking guarantee with no extra readiness assumption, so a block, wake, or cancellation can run immediately after any restored switch, refusal, fatal entry, or absorbed request.
- `gate_interrupt_noncontained_preserves_blockingRuntimeWellFormed` — Every interrupt outcome except contained cleanup keeps the full blocking guarantee; contained user faults are deliberately excluded because retiring a program can also retire endpoints other programs are waiting on, so that branch must first cancel the newly unauthorized waiters.
- `gate_interrupt_noncontained_preserves_deferredBlockingRuntimeWellFormed` — Every non-contained interrupt outcome also keeps the complete deferred-cancellation classification: a fatal entry changes only the two halt records, and timer, system-call, rejected, and already-halted outcomes leave the waiter, saved-context, retained, and switch banks exact.
- `gate_interrupt_preserves_deferredBlockingRuntimeWellFormed` — The complete interrupt family preserves the deferred blocking guarantee; the trusted identity binding is needed only by the contained-fault branch, and every other outcome preserves the guarantee with no extra fact.
- `gate_nmi_preserves_deferredBlockingRuntimeWellFormed` — An out-of-band non-maskable interrupt fail-stop keeps the deferred blocking guarantee: only the execution latch and the halt bit change, everything else stays exact, and an NMI arriving after a halt is absorbed.
- `gate_blockingRuntimePreserving_preserves_blockingRuntimeWellFormed` — Bookkeeping: one umbrella theorem that hands each member of the blocking-preserving operation family to its individual preservation proof.
- `dispatchHardware_deterministic` — Interrupt entry is deterministic: the same state and the same hardware frame always produce the same outcome.
- `dispatchHardware_preserves_wellFormed` — Hardware interrupt entry keeps the execution latch's records consistent in every mode; this is the public restatement of the internal fact used earlier.
- `attacker_registers_cannot_change_dispatch` — The general-purpose register contents attached to an interrupt have no influence whatsoever on how the interrupt is dispatched.
- `halted_entry_absorbing` — Once the execution latch is halted, any further interrupt is simply reported as already halted and changes nothing.
- `halted_gate_absorbing` — Once halted, the gate refuses every operation with the recorded halt diagnosis and the state stays exactly as it is.
- `halted_suffix_absorbing` — Once halted, running any finite list of further operations changes nothing at all.
- `observeDMAControl_invalid_suffix_absorbing` — A live PCI configuration snapshot that fails validation triggers the same fatal latch as the ordinary gate, after which every later public operation is absorbed byte-for-byte.
- `observeDMAControl_changed_suffix_absorbing` — A PCI snapshot that is valid but differs from the accepted one halts the kernel with its own diagnostic reason and enjoys the same total absorption of everything afterwards.
