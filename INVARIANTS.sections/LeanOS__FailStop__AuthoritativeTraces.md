# Blocking operations and whole traces through the authoritative gate

These theorems extend the authoritative gate's guarantees to blocking receive, send, and cancel, and then to whole sequences of operations: admissible traces preserve the combined invariant and device-access quarantine, and once the kernel halts every later operation is absorbed.

- `dispatchBlockingReceive_delivered_dormant_projections_exact` — When a receive finds a message already waiting, only the mailbox and the completion payload change; everything deferred cancellation watches stays literally the same.
- `dispatchBlockingReceive_idle_block_projection_exact` — When a receive finds nothing and the caller goes to sleep with no successor ready, exactly the caller's waiter and saved-context entries are recorded and the scheduler makes its one standard move, with the stored-register bank untouched.
- `dispatchBlockingReceive_selected_block_projection_exact` — When a receive puts the caller to sleep and hands the CPU straight to the next ready program, the kernel records exactly the caller's entries, consumes exactly the chosen successor's stored registers, and performs the one standard head-of-queue scheduler move.
- `dispatchBlockingReceive_blocked_current` — A stepping-stone fact: whenever a receive actually blocks, the program it blocked is provably the one the scheduler had selected as current beforehand.
- `blockingReceive_authoritativeOperationCompatible` — Every outcome of a blocking receive respects deferred cancellation: delivery changes nothing it watches, and blocking involves only the current caller and at most the head of the ready queue, neither of which can be a parked cancelled program.
- `authoritativeGate_blockingReceive_preserves_authoritativeRuntimeWellFormed` — Blocking receive preserves the complete combined guarantee, with no side-conditions asked of the caller.
- `dispatchBlockingReceive_blocked_not_retained` — A receive can never put a cancelled-and-parked identity to sleep: blocking requires being the current program, while parked identities are required to be idle.
- `dispatchBlockingSend_woke_not_retained` — A send can wake only a program with a saved waiter record, and no cancelled-and-parked program has one, so a send can never silently revive parked authority.
- `dispatchBlockingSend_woke_projection_exact` — A send that wakes a sleeper affects exactly one program: the woken waiter leaves the sleeping bank, joins the resumable bank, and no other program's scheduler or waiter records move.
- `dispatchBlockingSend_sent_dormant_projections_exact` — A send that merely deposits a message into a mailbox changes nothing that deferred cancellation watches except the mailbox itself.
- `blockingSend_authoritativeOperationCompatible` — Every outcome of a blocking send respects deferred cancellation: refusals change nothing, mailbox-only sends leave all watched records exact, and wakes touch only a receiver proved not to be parked.
- `authoritativeGate_blockingSend_preserves_authoritativeRuntimeWellFormed` — Blocking send preserves the complete combined guarantee, with no side-conditions asked of the caller.
- `dispatchBlockingCancel_retained_unchanged` — Cancelling a program that is already cancelled-and-parked does exactly nothing; its parked status itself proves there is no waiter left to remove.
- `dispatchBlockingCancel_cancelled_projection_exact` — A successful cancellation touches only the cancelled program: its waiter records and scheduler entry are cleared, and its released register state is placed at the front of the returned bank.
- `blockingCancel_authoritativeOperationCompatible` — Cancellation preserves every parked cancelled program: aiming at a parked identity changes nothing, and aiming at a genuine sleeper changes only that sleeper's own blocking, scheduler, and restored-context records.
- `authoritativeGate_blockingCancel_preserves_authoritativeRuntimeWellFormed` — Blocking cancellation preserves the complete combined guarantee, with no side-conditions asked of the caller.
- `selectUserReturn_authoritativeOperationCompatible` — Choosing return authority changes only the execution record, so its compatibility follows straight from the kernel's own guarantee with nothing extra supplied.
- `userReturn_authoritativeOperationCompatible` — Completing a return to a program may change the execution mode and the fatal latch, but never the waiter, deferred-cancellation, or saved-context stores.
- `restart_authoritativeOperationCompatible` — Restart changes nothing in any machine mode, so it trivially respects deferred cancellation.
- `authoritativeGate_selectUserReturn_preserves_authoritativeRuntimeWellFormed` — Choosing return authority always preserves the complete combined kernel guarantee.
- `authoritativeGate_userReturn_preserves_authoritativeRuntimeWellFormed` — Completing a return to a program always preserves the complete combined kernel guarantee.
- `authoritativeGate_restart_preserves_authoritativeRuntimeWellFormed` — Restart always preserves the complete combined kernel guarantee.
- `authoritativeOperationCompatible_of_admissible` — Every compatibility side-condition is derived from the kernel's own pre-existing guarantee: the contained-interrupt case consumes only its explicitly trusted identity fact, and every other ordinary, blocking, and drain operation needs nothing at all.
- `authoritativeGate_preserves_authoritativeRuntimeWellFormed_of_admissible` — The strengthened gate preserves the complete combined guarantee from the starting state's evidence alone, with no per-operation side-condition.
- `authoritativeGate_preserves_authoritativeRuntimeWellFormed` — The final public contract for one step: every authoritative operation preserves the complete combined kernel guarantee, given only that the guarantee held beforehand.
- `authoritativeGate_neutralConstructors_preserve_dmaQuarantined` — The self-contained neutral operations keep the device quarantine as a direct consequence of their full-state preservation, with no reliance on any still-open side-condition.
- `runAuthoritativeReadinessFreeMixedTrace_preserves_blockingRuntimeWellFormed` — Any finite mixture of operations from the readiness-free family preserves the complete scheduler, mailbox, sleeper, and saved-context guarantee, with each step consuming the guarantee established by the one before it rather than a separate per-state check.
- `readinessFreeMixedTrace_nonvacuous` — The readiness-free family is not empty: a concrete mixed run with lifecycle and revocation steps on both sides of a cancellation actually satisfies its entry condition, so the general theorem is not true merely for lack of examples.
- `runAuthoritativeOperations_preserves_authoritativeRuntimeWellFormed_of_compatible` — Every finite mixed run that carries per-step compatibility evidence preserves the complete combined guarantee; this version deliberately claims nothing for runs without such evidence.
- `runAuthoritativeOperations_preserves_authoritativeRuntimeWellFormed_of_admissible` — Arbitrary admitted finite runs preserve the combined guarantee, with each step's evidence rebuilt from the guarantee its predecessor established rather than promised in advance about a future state.
- `runAuthoritativeOperations_preserves_authoritativeRuntimeWellFormed` — The final public contract for whole runs: every finite list of authoritative operations preserves the complete combined guarantee, given only the guarantee at the start.
- `runAuthoritativeRevokeAfterSend_preserves_authoritativeRuntimeWellFormed` — Sending a sealed token and then revoking is just an ordinary run: it preserves the combined guarantee with no special admission for the pair.
- `runAuthoritativeStaleResumableContextTrace_preserves_authoritativeRuntimeWellFormed` — Retiring a program and then attempting to restore its stored registers is an explicit run: the resulting stale-context refusal falls under the same unconditional preservation and changes nothing.
- `authoritativeTraceCompatible_resumePreempts` — Any finite string of preemption attempts certifies itself: each step's evidence comes from the guarantee its predecessor preserved, never from the caller.
- `runAuthoritativeResumePreempts_preserves_authoritativeRuntimeWellFormed` — Arbitrary finite strings of save-and-restore preemptions — accepted switches, refusals, and fatal endings alike — preserve the complete combined guarantee.
- `authoritativeTraceCompatible_scheduleAdds` — Any finite string of run-queue admissions certifies itself: not-yet-cleaned-up candidates are refused harmlessly, and each accepted admission establishes what the next one needs.
- `runAuthoritativeScheduleAdds_preserves_authoritativeRuntimeWellFormed` — Arbitrary finite strings of run-queue admissions preserve the complete combined guarantee, however many candidates are refused for pending cleanup.
- `runAuthoritativeOperations_preserves_dmaQuarantined` — Every finite run keeps the exact boot-time device observation, proved directly over all operation kinds without needing the stronger combined guarantee or its evidence.
- `runAuthoritativeOrdinaryOperations_preserves_authoritativeRuntimeWellFormed` — Finite runs of ordinary operations need no sleeper or drain set-up between steps; their evidence composes step-local facts without assuming anything about intermediate results.
- `authoritativeGate_drainDeferred_preserves_deferredBlockingRuntimeWellFormed` — A public deferred-cleanup drain keeps the full parked-cancellation classification, whatever the outer machine latch says.
- `authoritativeGate_terminateSubject_preserves_deferredBlockingRuntimeWellFormed` — Explicitly terminating a named program crosses the gate while keeping the classification that later cleanup drains depend on.
- `authoritativeGate_terminateCurrent_preserves_deferredBlockingRuntimeWellFormed` — Terminating the scheduler's current program crosses the gate without weakening what a following cleanup drain needs.
- `authoritativeGate_interrupt_preserves_deferredBlockingRuntimeWellFormed` — Every inbound interrupt result keeps the complete deferred-cleanup guarantee, with no identity fact supplied from outside.
- `authoritativeGate_interrupt_preserves_authoritativeRuntimeWellFormed` — The interrupt path checks identities inside the transition itself: a match cleans up, a mismatch refuses with no change, and every outcome preserves the complete combined guarantee.
- `authoritativeGate_nmi_preserves_deferredBlockingRuntimeWellFormed` — The out-of-band NMI keeps the strongest deferred-cleanup guarantee, even on the mid-exception path that no ordinary operation may take.
- `runAuthoritativeDeferredDrains_preserves_deferredBlockingRuntimeWellFormed` — Finite runs made only of capacity-checked cleanup drains keep the complete deferred-cancellation guarantee: each success removes one parked entry, and every refusal or terminal step changes nothing.
- `runAuthoritativeTerminateSubjectThenDeferredDrains_preserves` — Terminating any live, blocked, deferred, or rejected program and then running any finite string of cleanup drains is one public run needing no readiness set-up between steps.
- `runAuthoritativeTerminateCurrentThenDeferredDrains_preserves` — Terminating the current program and then draining is likewise one public run; the termination itself establishes the exact classification each capacity-checked drain consumes.
- `runAuthoritativeInterruptThenDeferredDrains_preserves` — Every interrupt outcome may be followed by any finite string of cleanup drains without leaving the public gate or weakening the deferred guarantee between steps.
- `authoritativeTraceCompatible_deferredDrains` — Any finite string of cleanup drains certifies itself from any starting state, so it can be appended after any operation whose own evidence is closed.
- `authoritativeTraceCompatible_thenDeferredDrains` — Any single certified operation composes with any string of cleanup drains; the tail consumes the guarantee the head step establishes.
- `authoritativeTraceCompatible_interruptThenDeferredDrains` — An interrupt followed by cleanup drains forms one fully certified mixed run.
- `authoritativeTraceCompatible_terminateSubjectThenDeferredDrains` — Terminating a named program followed by cleanup drains forms one fully certified run, with nothing supplied from outside.
- `authoritativeTraceCompatible_terminateCurrentThenDeferredDrains` — Terminating the current program has the same closed run certificate as terminating a named one.
- `authoritativeTraceCompatible_nmiThenDeferredDrains` — An NMI halt followed by proposed cleanup drains is a fully certified run: the halt latch absorbs the tail while the complete guarantee is retained.
- `runAuthoritativeCompatibleInterruptThenDeferredDrains_preserves` — The general run theorem covers every interrupt followed by any finite string of cleanup drains while retaining the complete combined guarantee.
- `runAuthoritativeCompatibleTerminateSubjectThenDeferredDrains_preserves` — Terminating a named program and then draining preserves the complete combined guarantee, not merely its deferred part.
- `runAuthoritativeCompatibleTerminateCurrentThenDeferredDrains_preserves` — Terminating the current program and then draining likewise preserves the complete combined guarantee.
- `runAuthoritativeCompatibleNmiThenDeferredDrains_preserves` — An NMI halt followed by any drains is covered by the same general run theorem, so terminal absorption no longer rests on a weaker parallel argument.
- `runAuthoritativeNmiThenDeferredDrains_preserves` — An NMI halt plus any proposed drain tail is one public run: the first step preserves the strongest guarantee and latches the machine into terminal mode, so the entire tail is absorbed rather than papered over with an apparently coherent repair.
- `runAuthoritativeContainedInterruptThenDeferredDrains_preserves` — A contained exception and its cleanup-drain continuation form one public run: the trusted identity binding sets up the cleaned state, after which every drain rides the gate with no waiter, saved-context, or register-bank facts rebuilt in between.
- `authoritative_halted_suffix_absorbing` — Once the machine is halted, that is a result class of its own: any further mixture of ordinary operations, message delivery, sleep, wake, and cancellation is absorbed without effect.
- `observeDMAControl_invalid_authoritative_suffix_absorbing` — A live device observation the validator rejects halts the machine, and everything attempted afterwards — including blocking operations and cleanup drains — is absorbed.
- `observeDMAControl_changed_authoritative_suffix_absorbing` — A valid device observation that differs from the boot-accepted one halts the machine with its own distinct reason, and everything attempted afterwards is likewise absorbed.
- `authoritativeGate_rejection_reachable_witness` — A concrete example showing refusals really occur: from the boot state, whose waiter store is empty, a cancellation is refused without any change.
- `accepted_nmi_composite_atomicity` — An accepted NMI is one indivisible terminal step: once the halt latch is written, no lifecycle synchronization, no scheduler or preemption move, no return selection, and no ordinary handler runs.
- `rejected_user_return_composite_atomicity` — A refused return to a program is one indivisible step: it records the typed fatal reason, changes no lifecycle, authority, scheduler, or resource view, and absorbs everything attempted afterwards.
- `halted_never_accepts` — Once halted, the gate never reports any operation as completed, no matter what is submitted.
- `halted_terminal_non_resumption` — Once halted, no subsystem transition is accepted and no component of the terminal state can ever change.
- `fatal_atomicity` — When exception handling ends fatally, the program-lifecycle records are left exactly as they were: dying changes no ownership or roster data.
- `fatal_clears_copy_override` — Every fatal outcome ends with the kernel's temporary copy-permission override switched off, so no lingering bypass survives a halt.
- `interrupt_contained_requires_user` — A stepping-stone fact: the low-level classifier only ever labels an entry as contained when the interrupted code was running in user mode.
- `contained_requires_user_origin` — The full dispatcher can attribute a contained fault to a program only when the fault arrived from user mode.
- `double_fault_escalation` — A page fault arriving while another page fault is already being handled is escalated to the fatal double-fault halt.
- `kernel_fault_never_contained` — A fault raised from kernel mode is never contained and blamed on a program; no such outcome exists.
- `legacy_fatal_not_absorbing` — A negative check on the old design: in the action-only legacy model, a fatal kernel fault still leaves the machine willing to run a later system call, which is exactly the flaw the halt latch removes.
