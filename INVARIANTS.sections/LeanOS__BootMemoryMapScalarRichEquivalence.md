# Word-level boot decisions match the rich model everywhere

At boot, the kernel's decisions about the firmware's memory map travel as bare machine words: is this page usable, does anything off-limits overlap it, is it reserved by the kernel itself. The theorems in this file prove those words always mean exactly what the rich, fully spelled-out model of the decoded map and the reservation list says, for every possible map, reservation list, and page rather than for chosen examples. As a result, the first free page the kernel selects at boot is provably the same page the rich model would select, and no caller can slip substitute answers, a doctored reservation list, or a forged final state past the acceptance gates.

- `canonicalManifest_identity_valid` — The kernel's fixed way of building its reservation list always names each of the nine reserved-region identities exactly once and can never introduce an unknown identity, whatever range numbers are supplied.
- `withinPhysicalLimit_nat` — A stepping-stone fact used by later theorems: a memory range accepted by the word-level physical-bound check has exactly the arithmetic properties the rich reservation model needs.
- `roundInterval_of_withinPhysicalLimit` — Passing the word-level physical-bound check is by itself enough for the rich model to round the range to whole pages, with no extra promise about the range needed.
- `contained_withinPhysicalLimit` — If a range fits inside an outer range that itself lies under the physical bound, the inner range independently passes the rich rounding check.
- `roundedInterval_contained` — When one byte range contains another, rounding both outward to whole pages preserves that containment.
- `canonicalManifest_rounds_of_manifestValid` — Whenever the production manifest check passes, all nine reserved ranges round successfully to pages: the seven ranges owned by the loaded kernel image inherit its bound, while low memory and the boot-information range are checked on their own.
- `canonicalIntervals_contained_of_manifestValid` — The intervals forced by the manifest check, once rounded outward to pages, satisfy the rich model's requirement that image-owned regions stay inside the loaded image.
- `canonicalManifest_validate_of_rounds` — Once the nine ranges round successfully and that containment holds, the rich validator accepts exactly those intervals; the naming and count checks cannot fail because the construction itself fixes them.
- `canonicalManifest_validate_of_manifestValid` — The production manifest check alone is enough to build the complete reservation list and have the rich validator accept it.
- `initialized_intervals_eq_validated` — The reservation intervals retained by an accepted allocator start-up are the very same intervals the manifest validator returned.
- `roundInterval_contains_iff_byteRangeReserves` — Rounding a checked byte range outward to whole pages changes exactly nothing about which pages count as reserved by it.
- `rounded_ranges_reservedBy_iff` — For any list of reservations that round successfully, including the full nine-identity production list, each page is excluded after rounding exactly when it was excluded before, so no reservation can vanish in the translation.
- `manifestWord_eq_rounded_range_word` — The reservation answer word handed to the production consumer is therefore exactly the exclusion computed directly from all the original checked byte ranges.
- `field_words_iff_rich_predicates` — Bookkeeping: the three word-level answers (usable, blocked, reserved) taken together say exactly "this page is usable and unreserved" in the rich model's terms.
- `consume_exact_projection_iff` — The word-level consumer accepts a candidate page exactly when the rich model says that page is usable and unreserved; every ingredient is named explicitly, so none can be swapped for a substitute.
- `consume_canonical_projection_iff` — The same acceptance agreement with nothing left to the caller: the candidate and all three decision words are computed directly from the decoded entries, the checked intervals, and the page itself.
- `accepted_authority_projection_consumable` — An accepted end-to-end authority always yields a word-level summary the consumer will accept, with no extra conditions; the reverse direction, building authority from mere word-level acceptance, is deliberately not claimed here.
- `accepted_authority_field_words` — The three word-level decisions are fixed consequences of the returned authority, so publication can never ask a caller to restate usability or reservation status as separate yes-or-no inputs.
- `foldl_or_eq` — A small stepping-stone fact about running "or" down a list: the running tally ends up true exactly when it started true or some item matches.
- `eventFoldProjection_eq_rich` — The running tally used to build the free-memory bitmap is exactly the rich model's per-page classification, not an independent test someone could supply.
- `eventFoldFreeProjection_eq_richCandidateAccepted` — Layering the reservation list on top of that tally gives exactly the rich model's complete verdict for every page position in the bitmap.
- `scalarCandidateAccepted_eq_richCandidateAccepted` — Page by page, the word-level machinery and the rich model accept and reject exactly the same candidates, including every rejection before the first acceptance.
- `firstCandidateScan_unique` — A scan that walks pages in increasing order has exactly one possible first accepted answer.
- `authority_constructs_firstCandidateScan` — When the rich model rejects every page before its chosen one, that choice yields the exact first-accepted certificate for the word-level scan; the acceptance comes from the model's own evidence and the earlier rejections from the proven page-by-page agreement rather than being assumed.
- `firstCandidateScan_binds_rich_authority` — In reverse, any claimed word-level first result over the same decoded entries and checked intervals must be the rich model's chosen page, so a later page can never be passed off as first when both sides truly first accept an earlier one.
- `authority_continuation_binds_second_allocation` — Asking for a second page is a fresh allocation step, not a second bit read off the bitmap: any exposed follow-up result is exactly the allocation made from the state left after the first.
- `accepted_authority_publishes_after_rescan_and_scrub` — Once an independent rescan names the same selected page and the page-wiping step reports success, publication is fully determined by the complete authority, with nothing accepted from the caller; the wipe's success stays an explicit input until that step is wired into the allocator.
- `sharedAllocatorScrubState_accepts` — The page-wiping step accepts the very allocation the shared allocator made, with no second selection needed.
- `sharedAllocatorScrubState_selects` — What the wipe-and-publish step publishes is exactly the page selected by the decode, reserve, and allocate chain.
- `scrubbedPublication_complete_authority` — A wiped-and-published certificate ties all three production decisions to one complete result: the selection returns its page, publication derives its token without caller-supplied inputs, and the published page is entirely wiped and owned by the allocator.
- `scrubbedPublicationOfAuthority_complete` — Every authority yields that complete wipe-and-publish certificate whatever bytes happened to sit in the page beforehand, and the selection and the wipe are provably one and the same act rather than two merely matching observations.
- `scalarTerminalProjectionMatches_iff` — Spelling out the definition: the executable yes-or-no check "does the parser's final state agree with the authority" returns yes exactly when that agreement really holds.
- `runCanonical_acceptance_binding` — Acceptance of the composed pipeline binds everything at once, the raw bytes to the rich decoder, all nine reservation identities to the validator, and the selected authority to the word-level consumer, with no assumptions about test data, entry order, or memory size.
- `canonicalScalarInitial_of_authority` — Every authority sets up the word-level replay's starting state itself: its status, identity, size, phase, tallies, and target page all come from the authority and none from a caller.
- `canonicalScalarReplay_structurally_refines_authority` — Given one complete authority, the double-checked byte replay cannot end at any state other than the one the authority determines.
- `successfulScalarRichTraversal_agrees_authority` — The joint walk-through certificate is enough by itself to establish the four final fields the authorization gate rechecks, with no extra assumption about final values.
- `canonicalScalarReplay_agrees_authority` — Every authority necessarily passes the final-state comparison: the whole walk fixes completion, diagnostics, usable coverage, and blocked overlap.
- `scalarTerminalProjectionMatches_canonicalScalarReplay` — Bookkeeping: consequently the executable final-state check always answers yes for the replay an authority determines.
- `authorizeCanonical_acceptance_scalar_agreement` — Every accepted authorization binds the parser's actual final replay to the returned authority; any mismatch in status, diagnostics, or the two coverage answers causes rejection before any authority escapes.
- `authorizeCanonical_acceptance_binding` — Acceptance through the complete-output gate carries the raw-byte and reservation-list binding and additionally pins the caller's entire claimed summary to the returned authority.
- `authorizeCanonical_checkedReplay_semantic_agreement` — At an accepted boundary, the byte-level replay, the word-level replay, and the complete authority all report one and the same final result; in particular the usable and blocked answer words are the classifications of the actual decoded entries, not substitutes.
- `authorizeCanonical_scalarReplay_projection_binding` — The authorization gate feeds the real replay's final fields, not stand-ins from the rich side, into the production consumer and returns exactly the selected page.
- `runCanonical_raw_bytes_extensional` — Identical raw bytes and identical reservation words can never produce two different complete results, so the whole pipeline is deterministic in its inputs.
