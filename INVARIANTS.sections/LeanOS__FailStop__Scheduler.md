# Terminating programs and scheduling them safely

These theorems show that terminating a program removes every scheduler, saved-context, and transfer reference to it in the same step, and that adding, removing, and selecting programs for scheduling preserve the global runtime invariant.

- `terminateSubject_accepted_cleans_runtime_references` — When the kernel accepts a request to terminate a program, that program is dead, cannot remain current or queued, keeps no blocked, saved, or deferred context, and no in-flight sealed gift descended from it survives.
- `terminateSubject_accepted_removes_owned_address_spaces` — Accepted termination removes every address-space ownership entry for the retired program in the same lifecycle publication that makes its identity dead.
- `terminateSubject_accepted_defers_invalidated_waiter` — Terminating an endpoint's owner cannot strand a peer waiting on that endpoint: the peer's saved context moves into the deferred-cancellation bank and the dead endpoint's mailbox is emptied in the same accepted step.
- `gate_terminateSubject_accepted_preserves_schedulerWellFormed` — Accepted termination keeps both scheduler views consistent, even in the corner case where cleanup leaves one lone current program with no queued peer; that state is fine because the next timer switch simply refuses.
- `gate_terminateSubject_accepted_preserves_resumableContextBank` — Accepted termination keeps the saved-context bank healthy: its capacity, uniqueness, validity, exclusion of the current program, and agreement with the ready queue all survive, including cleanup of the final queued peer.
- `installTerminatedResumable_cleanup_preserves_runtimeWellFormed` — The kernel's shared cleanup publisher preserves the whole-kernel guarantee for any program identifier; both explicit termination and interrupt-contained user faults route through this one boundary.
- `gate_terminateSubject_accepted_preserves_runtimeWellFormed` — Accepted termination of a program is one complete operation: lifecycle, resource, context, mailbox, and sealed-offer cleanup are published to every duplicated view atomically while the kernel-wide guarantee holds.
- `gate_terminateSubject_accepted_flushes_translations` — Accepted termination is also the moment the translation cache is fully flushed, so memory the dead program could reach through several roots cannot be reused while any stale cached translation survives.
- `terminateSubject_operationPreservesRuntimeWellFormed` — Every public termination request preserves the guarantee: never-created or already-dead targets are refused without change, and acceptance performs the complete lifecycle, resource, context, mailbox, and transfer cleanup.
- `scheduleNext_accepted_none_preserves_runtimeWellFormed` — The raw dispatch operation succeeds only by selecting nobody, and in that case the kernel state is preserved byte-for-byte alongside the reported success.
- `scheduleNext_rejected_preserves_runtimeWellFormed` — Bookkeeping: a refused raw dispatch leaves the kernel state literally unchanged.
- `scheduleYield_rejected_preserves_runtimeWellFormed` — Bookkeeping: a refused raw yield leaves the kernel state literally unchanged.
- `scheduleTick_rejected_preserves_runtimeWellFormed` — Bookkeeping: a refused raw timer tick leaves the kernel state literally unchanged.
- `terminateCurrent_rejected_preserves_runtimeWellFormed` — Bookkeeping: a refused current-program termination, such as when nothing is running, leaves the kernel state literally unchanged.
- `terminateCurrent_operationPreservesRuntimeWellFormed` — Terminating whichever program is current preserves the guarantee: on a coherent kernel it selects the same live victim as explicit termination and performs the same complete cleanup, with busy and halted modes absorbed by the gate.
- `scheduleRemove_operationPreservesRuntimeWellFormed` — Removal from the ready queue preserves the guarantee: acceptance also consumes the saved context and evicts active translations, and the case with no peer to run is a refusal that changes nothing.
- `capabilityRevoke_then_scheduleRemove_preserves_runtimeWellFormed` — Revoking a permission and then removing a program from the queue compose safely: the removal starts from the exact post-revocation state, never from a stale pre-revocation view.
- `capabilityRevokeSubtree_then_scheduleRemove_preserves_runtimeWellFormed` — The same composition holds after lineage-wide revocation: every permission view sees the revoked state before scheduler and saved-context cleanup runs.
- `createSubject_operationPreservesRuntimeWellFormed` — Creating a program preserves the guarantee: it only ever promotes one fresh identity, so every existing resource, scheduler, mailbox, context, and translation fact remains valid when the new roster is published.
- `gate_scheduleAdd_accepted_runtimeWellFormed_requires_staged_context` — The gate can report a successful queue admission only if the admitted program's kernel-owned starting context was already staged beforehand.
- `schedulerAdd_accepted_projections` — Bookkeeping: an accepted admission keeps the program roster unchanged and appends exactly the admitted program to the ready queue.
- `gate_scheduleAdd_accepted_preserves_runtimeWellFormed` — Accepted queue admission preserves the whole-kernel guarantee when the program's starting context was staged: nothing changes except the ready queue, which both scheduler views observe identically.
- `scheduleAdd_missing_context_rejected_atomic` — A program without a staged kernel-owned context can never be admitted, even when the raw scheduler would have accepted it; the attempt changes nothing.
- `scheduleAdd_operationPreservesRuntimeWellFormed` — Queue admission preserves the guarantee in every case: raw refusals and missing-context failures change nothing, while every reported success publishes the staged context owner consistently.
- `scheduleNext_operationPreservesRuntimeWellFormed` — Raw dispatch preserves the guarantee: selecting nobody succeeds without changing anything, and any selection that would need a context restore is refused without change.
- `scheduleYield_operationPreservesRuntimeWellFormed` — Raw yield preserves the guarantee because it can never act: without an outgoing saved context every attempt while running is refused, and every other mode is absorbed by the gate.
- `scheduleTick_operationPreservesRuntimeWellFormed` — Raw timer tick preserves the guarantee for the same reason; timer-driven switching lives only in the resumable preemption operation.
