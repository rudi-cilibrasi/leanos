# The kernel's headline security claims

This file is the kernel's master security contract: each theorem here independently restates one advertised promise, matching a row in the project's security-claims document, so any change to an underlying proof must show up visibly here. Together the theorems cover the whole advertised surface: single-processor boot, direct hardware-port lockdown, device memory-access quarantine and the IOMMU, identity lifetimes, the single system-call gate and all its operations, fault containment, safe returns to user programs, translation-cache hygiene, and the fail-stop halt. Many entries are concrete demonstrations ("witnesses") showing the promises are not vacuously true, or bookkeeping facts about the example states those demonstrations use.

- `single_core_boot_admission_confined` — When the kernel accepts the machine description at boot, that description shows exactly one enabled processor, which is the very processor running the boot code, and nothing the admitted kernel can do afterwards can ever announce the start of a second processor.
- `direct_port_user_denial_preserves_devices` — Words a user program supplies for a hardware-port access can never select a kernel purpose or change any device; the kernel answers with the modeled protection fault instead.
- `direct_port_kernel_operation_confined` — The kernel itself may perform a port operation only with live kernel privilege, an exact pre-reviewed manifest entry naming the purpose, port, direction, and width, and fresh control settings.
- `direct_port_denial_survivor_contained` — When a user program attempts a forbidden port access, the kernel denies it with all devices untouched, then terminates that program through the standard cleanup step, letting a survivor run; the forbidden port, value, and width words never reach any kernel operation, and control never returns to the offending program.
- `dma_quarantine_preserves_complete_projection` — With the boot-time device quarantine accepted and the stated bus-master control contract in force, no quarantined device can change any part of the kernel's modeled memory.
- `dma_quarantine_nonfatal_trace_preserves_complete_projection` — The quarantine keeps holding across any finite run of continuing control operations and access attempts by unowned devices, with every modeled memory view unchanged throughout.
- `dma_quarantine_q35_nonvacuous` — Not an empty promise: the pinned machine configuration really produces an accepted, non-empty quarantine of concrete devices.
- `dma_quarantine_q35_trace_nonvacuous` — The finite-run version is also demonstrated on a real example that mixes an ordinary control step with an access attempt by an actually present device (the VGA display adapter).
- `dma_quarantine_global_runtime_preservation` — The kernel's one authoritative running state carries the exact device-control snapshot accepted at boot, and every finite sequence of later steps of any kind keeps that non-empty deny-all quarantine intact.
- `dma_quarantine_global_runtime_nonvacuous` — A concrete accepted boot input really produces a running kernel satisfying the global quarantine claim's starting conditions.
- `dma_authoritative_unowned_device_preservation` — If a named present device honors an explicitly assumed hardware contract over the live device controls, then that device cannot change any modeled memory; the contract itself is an assumption the caller supplies, not something these theorems prove.
- `dma_invalid_live_control_is_fatal_and_absorbing` — If a live check of the device controls comes back malformed, the kernel halts fatally, and every operation proposed after that is swallowed without effect.
- `dma_changed_live_control_is_fatal_and_absorbing` — If the live device controls are well formed but differ from what was accepted at boot, the kernel likewise halts fatally and stays halted forever.
- `dma_changed_live_control_nonvacuous` — Demonstrated concretely: the sample boot state plus a single drifted device-control bit really satisfies the drift check's conditions, triggers the fatal halt, and then swallows everything proposed afterwards.
- `iommu_finite_read_confidentiality` — What a device learns through any finite sequence of authorized reads depends only on the bytes it was actually allowed to read; changing any byte outside those exact ranges changes nothing the device sees.
- `iommu_finite_write_integrity` — Across any finite run of device activity, every byte of a frame that is protected, physically unassigned, or owned by someone else stays exactly the same.
- `iommu_translation_nonforgery` — Every successful device address translation is tied to the kernel's own existing record, binding the source, the assignment generation, the domain, the owner, and the live backing frame; a device can never forge one.
- `iommu_teardown_cleanup` — When the kernel tears down a device assignment, every address mapping belonging to exactly that generation-checked assignment is removed.
- `iommu_reachable_frame_release_denied` — The kernel refuses to release a memory frame that a device can still reach through an active mapping; the refusal is a typed answer that leaves the complete state unchanged.
- `iommu_fatal_suffix_absorbing` — Once the kernel has halted fatally, every finite sequence of later device-control requests leaves the entire device-translation state untouched.
- `lifetime_identity_no_reuse` — No matter what finite sequence of lifecycle operations happens, the identity counters and history stay in agreement, a retired object identity or terminated program identity can never come back to life, and an identity supply that has run out stays run out.
- `lifetime_identity_no_reuse_nonvacuous` — Not vacuous: a concrete sample system satisfies the required invariant and survives a mixed run of creations and retirements across both identity families and all three object kinds.
- `kernel_transition_deterministic` — The kernel's first modeled state machine always gives one and only one outcome for a given state and command.
- `kernel_transition_preserves_wellFormed` — That first state machine keeps its state well formed through every step.
- `capability_copy_no_authority_amplification` — Copying a permission token can never manufacture authority out of nothing; every copy traces back to authority already held.
- `frame_ownership_exclusive` — A memory frame never has two different owners at once.
- `admitted_frame_budget_isolation` — A program with an available committed frame in its own budget, and valid inputs, can always allocate, no matter how much its peers have consumed; one program cannot starve another out of its own reservation.
- `page_table_distinct_spaces_separated` — Two address spaces backed by distinct encoded frames give distinct results when the same address is looked up; the spaces are genuinely separate.
- `syscall_authority_confinement` — Nothing a program writes into a system-call request can add capability authority.
- `failstop_halted_suffix_absorbing` — After a fatal halt, every proposed follow-on operation is swallowed without effect.
- `composite_authoritative_compatible_gate_contract` — The kernel's single entry gate handles both ordinary and blocking operations under one lock with one typed reply, validates identities inside the transition itself, makes every classified denial all-or-nothing, and once fatal swallows any mixture of later operations.
- `composite_authoritative_compatible_mixed_trace_preserves_runtimeWellFormed` — A stepping-stone fact used by later theorems: any certified finite mixture of ordinary and blocking operations preserves the complete global invariant, with the certificate supplied rather than derived.
- `composite_authoritative_admitted_trace_preserves_runtimeWellFormed` — Any finite sequence of operations through the entry gate preserves the complete global invariant, starting from nothing more than the invariant holding at the outset.
- `composite_authoritative_mapping_then_blocking_preserves_runtimeWellFormed` — Changing memory mappings or protections never disturbs what blocking operations rely on, so any mapping change can be followed directly by any block, wake, or cancellation.
- `composite_authoritative_syscall_then_blocking_preserves_runtimeWellFormed` — Every system call, however attacker-chosen its contents and whether accepted or denied, leaves the kernel ready for any blocking operation to follow immediately.
- `composite_authoritative_transferOffer_then_blocking_preserves_runtimeWellFormed` — Offering a sealed capability transfer leaves the kernel ready for any block, wake, or cancellation to follow immediately.
- `composite_authoritative_transferAccept_then_blocking_preserves_runtimeWellFormed` — Accepting a sealed capability transfer, which fills a checked-empty slot and consumes the sealed mailbox, likewise leaves the kernel ready for any blocking operation to follow immediately.
- `composite_authoritative_capabilityCopy_then_blocking_preserves_runtimeWellFormed` — Copying a capability only ever adds authority, never removing anything a waiting program relies on, so every copy outcome can be followed immediately by any blocking operation.
- `composite_authoritative_capabilityRevoke_then_blocking_preserves_runtimeWellFormed` — Revocation refuses, before acting, to remove receive authority a waiting program is using, so every accepted revocation and every denial can be followed immediately by any blocking operation.
- `composite_authoritative_createSubject_then_blocking_preserves_runtimeWellFormed` — Creating a new program only adds lifecycle facts, so every creation outcome can be followed immediately by any blocking operation.
- `composite_authoritative_schedulerAdmission_then_blocking_preserves_runtimeWellFormed` — Admitting a program to the run queue adds a runnable identity that cannot be confused with any waiting one, so every admission outcome can be followed immediately by any blocking operation.
- `composite_authoritative_raw_scheduler_then_blocking_preserves_runtimeWellFormed` — Raw scheduler selection with no kernel-held context to restore is neutral toward waiting programs, so its empty dispatch and forced denials can be followed immediately by any blocking operation.
- `composite_authoritative_resumePreempt_then_blocking_preserves_runtimeWellFormed` — Preempting and resuming programs, whether it succeeds, is denied, turns fatal, or is refused at the busy gate, always leaves the kernel ready for any blocking operation to follow.
- `composite_authoritative_noncontained_interrupt_then_blocking_preserves_runtimeWellFormed` — Any inbound interrupt outcome that does not terminate a contained user program leaves the kernel ready for any block, wake, or cancellation to follow.
- `composite_authoritative_gate_rejection_reachable_witness` — The gate's classified rejections are demonstrated on a real state, the freshly booted kernel with no waiting programs, rather than holding vacuously.
- `composite_gate_sealed_receive_preserves_runtimeWellFormed` — Trying to receive from a sealed mailbox is refused in a way that preserves the complete invariant and tells the caller exactly why: sealed transfers must go through the acceptance operation instead.
- `composite_gate_data_send_preserves_runtimeWellFormed` — An accepted data send preserves the complete invariant and reports exactly one typed success.
- `composite_gate_data_receive_preserves_runtimeWellFormed` — An accepted data receive preserves the complete invariant and reveals exactly the sender and message the kernel itself selected.
- `composite_blocking_gate_preserves_contextWellFormed` — Every typed block, wake, cancellation, and rejection keeps the record of who is waiting in exact agreement with whose saved context the kernel holds; successful wakes and cancellations additionally pass through the checked context-restoration boundary.
- `composite_blocking_gate_preserves_blockingRuntimeWellFormed` — The complete typed blocking gate preserves the combined global and waiter-and-context invariant without the caller having to classify what happened.
- `composite_contained_fault_cleanup_preserves_context_boundary` — A stepping-stone fact used by later theorems: cleanup after a contained fault keeps the scheduler and lifecycle views synchronized, keeps waiters and saved contexts in exact agreement, and moves invalidated peers into a typed deferred-cancellation state.
- `composite_contained_fault_cleanup_removes_faulting_subject` — A stepping-stone fact used by later theorems: the faulting program is removed, in one composite step, from every published view, including lifecycle, scheduler, resumable, waiter, and blocked-context records.
- `composite_contained_fault_cleanup_clears_faulting_deferred` — Bookkeeping: after that cleanup, the faulting program is also absent from the deferred-cancellation bank.
- `composite_deferred_cancel_drain_rejection_atomic` — Every typed denial of a deferred-cancellation drain, including when the ready queue or context bank is full, changes nothing at all.
- `composite_deferred_cancel_drain_success_boundary` — A successful drain reserves room in both finite banks and publishes exactly the retained context through synchronized scheduler views.
- `composite_deferred_cancel_public_gate_and_trace_preserve` — A stepping-stone fact used by later theorems: capacity-checked deferred cancellation is an ordinary public gate operation, and one step or any finite run of them preserves the global invariant and the exact classification of every retained context.
- `composite_interrupt_then_deferred_trace_preserves` — Any inbound interrupt followed by any finite run of deferred-cancellation drains preserves the invariant; only the contained-fault path uses up the identity check, and every other interrupt outcome leaves the deferred store and context banks exactly as they were.
- `composite_nmi_then_deferred_trace_preserves` — A stepping-stone fact used by later theorems: a non-maskable interrupt sends the kernel into fail-stop while preserving the deferred invariant, and the halted state then swallows every proposed drain.
- `composite_contained_fault_then_deferred_trace_preserves` — A stepping-stone fact used by later theorems: contained-fault cleanup and any finite tail of deferred cancellations all run through the one public gate while preserving the complete deferred invariant.
- `composite_contained_fault_cleanup_and_deferred_trace_contract` — The stable combined promise bundling the contained-cleanup boundary together with its public deferred-drain continuation.
- `composite_blocking_gate_rejection_preserves_runtimeWellFormed` — Every ordinary denial at the typed blocking gate returns the state literally unchanged, so the full invariant is preserved for free.
- `composite_blocking_gate_rejection_reachable_witness` — Demonstrated on a real state: the freshly booted kernel classifies an attempt to cancel program 1 as an ordinary, all-or-nothing "not waiting" denial.
- `composite_gate_transferOffer_preserves_runtimeWellFormed` — Every possible sealed-transfer offer, from malformed or stale handles through the accepted pending-mailbox update, preserves the complete global invariant.
- `composite_gate_transferAccept_preserves_runtimeWellFormed` — Every possible sealed-transfer acceptance, including handle and slot rejections as well as successful installation of the authority, preserves the complete global invariant.
- `composite_gate_typed_result_contract` — Every completed public gate step names exactly which operation ran (the holder of the running lock, or the explicitly out-of-band non-maskable interrupt), its exact typed reply, and its exact resulting state; every classified rejection leaves the state whole and preserves the global invariant whenever it held beforehand.
- `composite_gate_authority_confinement` — Every authority-bearing operation acts as the currently running program in the currently active address space, both chosen by the kernel's own execution state; no operation argument can smuggle in a different privileged identity.
- `composite_gate_control_preserves_runtimeWellFormed` — Both control operations preserve the complete invariant in every execution mode, including exactly what the busy and halted gate rejections must keep intact.
- `composite_gate_mapping_preserves_runtimeWellFormed` — Every kernel-confined raw mapping operation preserves the complete invariant in every execution mode.
- `composite_gate_syscall_preserves_runtimeWellFormed` — Every fixed-width system-call request, however attacker-chosen, preserves the complete invariant; who is calling and which address space is active remain the kernel's own determinations, never the caller's.
- `composite_gate_schedulerAdmission_preserves_runtimeWellFormed` — Run-queue admission accepts any program identifier as a request, atomically refuses one that has no kernel-held context, and preserves the complete invariant for every typed result.
- `composite_gate_termination_preserves_runtimeWellFormed` — Any program identifier is a valid termination request; refusals change nothing, and acceptance retires the program's resources and removes every scheduler, context, mailbox, and sealed-transfer reference to it while preserving the complete invariant.
- `composite_gate_termination_cleans_runtime_references` — A stepping-stone fact used by later theorems: an accepted termination removes the dead identity from every modeled scheduler and saved-context view, including the deferred-cancellation bank, and cancels every one of its sealed transfers in the same step.
- `composite_gate_termination_defers_invalidated_peer` — A stepping-stone fact used by later theorems: when termination retires a message endpoint, every peer waiting on it is detached with its saved context kept for a checked later drain, and that endpoint's mailbox is cleared.
- `composite_legacy_operation_mixed_trace_preserves_runtimeWellFormed` — Any finite interleaving of every operation in the older public surface preserves that surface's global invariant whatever the result class; blocking operations and deferred drains sit outside this older surface and its invariant.
- `composite_authoritative_ordinary_trace_preserves_runtimeWellFormed` — A stepping-stone fact used by later theorems: any finite list of ordinary gate operations preserves the complete folded invariant using only step-by-step local reasoning, never assuming the conclusion partway through.
- `composite_authoritative_readinessFree_mixed_trace_preserves` — A stepping-stone fact used by later theorems: any finite interleaving of the ordinary family with arbitrary blocking operations preserves the complete blocking invariant, using a certificate that does not depend on the state and so replaces the older recursive readiness check.
- `composite_terminateSubject_then_deferred_trace_preserves` — A stepping-stone fact used by later theorems: explicitly terminating any chosen program keeps the deferred-cancellation invariant that any finite drain tail then relies on.
- `composite_terminateCurrent_then_deferred_trace_preserves` — A stepping-stone fact used by later theorems: terminating the scheduler-selected current program likewise establishes and keeps the deferred-cancellation invariant for any finite drain tail.
- `composite_gate_preserves_direct_port_boundary` — No public gate step, alone or in any finite mixture, changes the port-access controls or the device view in the slightest, so the deny-all policy for user port access can never be loosened or "repaired" by an unrelated operation.
- `composite_boot_runtime_wellFormed` — Every successfully compiled bounded boot plan yields an idle kernel satisfying the complete global invariant before any program or trusted return identity is admitted.
- `composite_boot_runtime_reachable_witness` — Demonstrated concretely: the repository's own accepted sample boot input reaches that globally well-formed initial kernel.
- `registeredMixedTrace_registered` — Bookkeeping: every operation in the sample mixed run used by the demonstration below is one of the registered public operation kinds.
- `composite_legacy_operation_mixed_trace_reachable_witness` — Demonstrated concretely: from the sample boot plan, a finite run mixing attacker-controlled system calls, messaging, sealed transfers, capability copies and revocations, mappings, creation and termination, scheduler cleanup, return selection, and restart keeps the older invariant intact; it is not evidence for the newer folded blocking invariant.
- `interrupt_entry_context_binding` — Every normalized interrupt record takes its authority-bearing fields from the kernel-owned input, never from anywhere else.
- `page_fault_provenance_binding` — An accepted page-fault record is pinned down completely: the right interrupt number, the exact error, access, and faulting-address details, a canonical address, agreeing origin, and confinement to the kernel-owned context.
- `page_fault_authorization_context_binding` — The page-fault handling boundary authorizes only independently supplied program and address-space identities that fit one canonical encoding, and decoding them back yields exactly the trusted identities rather than a wrapped-around look-alike.
- `page_fault_active_space_containment_agreement` — A successful strengthened page-fault containment uses exactly the authorized identities, checks the faulting address only inside the kernel-selected active page-table root, validates the complete decoded live report against the plan, the lifecycle, and an empty matching translation-cache entry, and admits only an error class that matches the live page table's own denial.
- `privilege_entry_stack_budget_sound` — Accepted stack authorization for ordinary kernel entry names the exact valid guarded layout and carries a checked byte margin, without changing the modeled state.
- `privilege_entry_control_single_mechanism` — Every accepted processor configuration enables exactly one doorway into the kernel: the reviewed, manifest-backed software-interrupt mechanism.
